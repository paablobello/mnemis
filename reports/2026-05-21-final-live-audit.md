## Residual Findings

Status after follow-up implementation: the residual findings below are closed by clearer setup documentation, env guidance, and repeatable live QA scripts. Semantic Scholar remains intentionally optional.

### Low - Semantic Scholar is rate-limited without an API key

The academic discovery flow degrades correctly through OpenAlex, but live QA received HTTP 429 from Semantic Scholar. This is expected because `SEMANTIC_SCHOLAR_API_KEY` is intentionally not configured. Production quality is still acceptable because OpenAlex returned usable paper/PDF candidates, but Semantic Scholar should be treated as best-effort unless a key is added.

### Low - PDF sidecar must be running when forcing sidecar extraction

`MNEMIS_PDF_EXTRACTOR_URL` points to `http://localhost:8790/extract`. The endpoint was initially down until the Docker `pdf` profile was started. After running `docker compose -f docker/docker-compose.yml --profile pdf up -d pdf-extractor`, health passed and forced sidecar extraction worked with Docling and GROBID.

### Informational - MCP should be launched via the package bin/build, not the Bun filter wrapper

The real MCP build at `apps/mcp/dist/index.js` worked over stdio and exposed all tools. The `bun --filter @mnemis/mcp start` wrapper exits when invoked without a persistent MCP client stdin, so agent configs should keep using the packaged `@mnemis/mcp` entrypoint generated by `mnemis init` or the built dist entrypoint.

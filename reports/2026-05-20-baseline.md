## Results

| variant                | nDCG@10 | MRR@10 | Recall@5 | embedding | reranker                         |
| ---------------------- | ------- | ------ | -------- | --------- | -------------------------------- |
| keyword (no rerank)    | 0.197   | 0.233  | 0.192    | —         | —                                |
| keyword + local rerank | **0.433** | **0.481** | **0.317** | —     | `Xenova/bge-reranker-base` (q8 ONNX) |
| hybrid (no rerank)     | 0.197   | 0.233  | 0.192    | —         | —                                |
| hybrid + Voyage rerank | n/a     | n/a    | n/a      | —         | n/a                              |

Hybrid collapsed to `keyword_only` on this run because the environment had no
`VOYAGE_API_KEY` configured, so the worker never wrote chunk embeddings. The
search service falls back gracefully to pure BM25 in that case.

## Reading the numbers

- **Local BGE reranker more than doubles nDCG and MRR over plain BM25** in this
  corpus, while raising Recall@5 by ~65 % (0.192 → 0.317). That confirms the
  retrieval pipeline benefits even when vectors are unavailable: the
  cross-encoder reorders the BM25 top-50 pool meaningfully.
- The first request through the local reranker spent ~30 s downloading the
  model (~120 MB on disk after q8 quantization). Subsequent requests run in
  150–500 ms for ten documents. The default model id is
  `Xenova/bge-reranker-base`; override with `MNEMIS_LOCAL_RERANK_MODEL`.

## What we could not measure

- **Voyage embeddings + hybrid retrieval**: requires a `VOYAGE_API_KEY` in the
  environment. Without it, `getEmbeddings()` returns `null` and the worker
  skips the embed step. Filling that in and rerunning `bun run benchmark`
  should produce the missing rows.
- **Voyage rerank** (`MNEMIS_RERANK_PROVIDER=voyage`): same prerequisite as
  above.

## Caveats

- The dataset is intentionally small (10 queries) and self-corpus, so the
  numbers reflect Mnemis-specific vocabulary. Inflate the dataset before
  publishing public quality claims.
- The original `Xenova/bge-reranker-v2-m3` model is currently gated on
  Hugging Face (`Unauthorized access to file`). We default to
  `Xenova/bge-reranker-base`, which is smaller (278 M params vs 568 M) but
  publicly downloadable and works out of the box.
- Variants were run sequentially against the same indexed source
  (`MNEMIS_BENCHMARK_SOURCE_ID=82d3c67e-7624-448e-8a11-54afe827ddb1`), with
  the API process restarted between configurations to swap
  `MNEMIS_RERANK_PROVIDER`. Worker stayed the same across runs.

## How to reproduce

```bash
# 1. fresh schema + bootstrap a workspace with a key
bun run docker:up
bun run db:push:ci
bun run db:bootstrap -- --email bench@mnemis.test --workspace mnemis-benchmark

# 2. start the worker + api with local sources allowlisted
export MNEMIS_ALLOW_LOCAL_SOURCES=true
export MNEMIS_LOCAL_SOURCE_ROOTS=$(pwd)
bun run worker:dev &

# 3. run with each provider (kill+restart the API between runs)
bun run api:dev &
bun run benchmark > reports/raw/baseline-none.txt
kill %2 && MNEMIS_RERANK_PROVIDER=local bun run api:dev &
MNEMIS_BENCHMARK_SOURCE_ID=<id from run 1> bun run benchmark > reports/raw/baseline-local.txt
```

Set `VOYAGE_API_KEY` and `ANTHROPIC_API_KEY` before the runs to also exercise
the hybrid and Voyage rerank paths.

# Mnemis self-corpus retrieval baseline — 2026-05-20

| Field | Value |
| --- | --- |
| Date | 2026-05-20 |
| Dataset | `packages/eval/data/mnemis-self/queries.json` — 10 queries, manual qrels |
| Corpus | the Mnemis repo itself, indexed via `config.localPath` |
| Chunks indexed | 752, of which 751 carry Voyage embeddings (1 empty chunk skipped) |

## Results

`keyword` runs only Postgres BM25; `hybrid` adds Voyage vector retrieval and
fuses with RRF (k=60). Each row is the same retrieval policy followed by the
listed reranker.

| variant | reranker | nDCG@10 | MRR@10 | Recall@5 |
| --- | --- | --- | --- | --- |
| keyword | — | 0.197 | 0.235 | 0.192 |
| keyword | `Xenova/bge-reranker-base` (ONNX q8) | 0.421 | 0.483 | 0.367 |
| keyword | Voyage `rerank-2.5` | **0.509** | **0.575** | **0.617** |
| hybrid | — | 0.043 | 0.233 | 0.108 |
| hybrid | `Xenova/bge-reranker-base` (ONNX q8) | 0.346 | 0.439 | 0.317 |
| hybrid | Voyage `rerank-2.5` | 0.441 | 0.525 | 0.467 |

## Reading the numbers

- **Voyage rerank-2.5 remains the clear quality win**: on top of plain keyword
  it lifts nDCG@10 from 0.197 → 0.509 (+158%) and **triples Recall@5**
  (0.192 → 0.617). Pair with hybrid for the safety net on semantic queries.
- **Local BGE-base** still doubles nDCG/MRR over no-rerank and is the obvious
  free fallback (~120 MB on disk).
- **Hybrid alone underperforms keyword on lexical queries**: the dataset is
  full of "where is X" style queries that BM25 handles well; the Voyage
  vector tier surfaces semantically-close but off-topic chunks until a
  reranker reorders the pool.

## Cost-driven change in this run: `voyage-3-large` → `voyage-4-large`

The previous baseline used `voyage-3-large` ($0.18 / M tokens, no free tier).
Voyage's current pricing puts that model in the "older" bucket and prices
the modern `voyage-4-large` at $0.12 / M tokens with **200 M free per
account per month** ([pricing
docs](https://docs.voyageai.com/docs/pricing)). For our 752-chunk Mnemis
corpus (~540 K tokens per full re-index), that means dropping from
$0.10 / re-index to free until ~370 re-indexes per month.

Quality side-by-side (both runs without contextual prefix, same queries
and qrels, same Voyage rerank-2.5 model where applicable):

| variant | reranker | voyage-3-large (prev) | voyage-4-large (this run) |
| --- | --- | --- | --- |
| keyword | — | 0.193 / 0.229 / 0.192 | 0.197 / 0.235 / 0.192 |
| keyword | local | 0.414 / 0.492 / 0.317 | 0.421 / 0.483 / 0.367 |
| keyword | voyage | 0.502 / 0.575 / 0.567 | **0.509 / 0.575 / 0.617** |
| hybrid | — | 0.057 / 0.164 / 0.108 | 0.043 / 0.233 / 0.108 |
| hybrid | local | 0.361 / 0.494 / 0.317 | 0.346 / 0.439 / 0.317 |
| hybrid | voyage | 0.441 / 0.525 / 0.467 | 0.441 / 0.525 / 0.467 |

Quality is within ±0.01 nDCG across the board — except for `keyword +
Voyage rerank Recall@5`, which improves by 0.05 absolute (+9%). The switch
is a clear win.

## What we tried: enabling Anthropic contextual prefix

A separate run with `ANTHROPIC_API_KEY` set (so `apps/worker/src/contextual-prefix.ts`
generated Haiku 4.5 prefixes for 91 doc chunks) **lowered** every metric:
keyword + Voyage rerank dropped from 0.509 → 0.381 nDCG@10. The most
likely cause is vocabulary dilution: Haiku's prefix repeats domain terms
across sibling chunks (e.g. "Mnemis", "cron", "embedding"), which inflates
DF and flattens BM25 scoring on our highly lexical query mix.

Contextual prefixes are documented as a +49% retrieval boost on natural
prose. On a code corpus with terse, terminology-heavy queries they are at
best neutral and at worst harmful. **Default behaviour stays unchanged**
(`contextualPrefixMode: 'auto'` — only fires for `docs_site` and
markdown-tagged chunks), but the report's headline numbers are the
no-prefix run because that's a fair comparison with the previous
baseline. Raw output for the prefix run is at
`reports/raw/baseline-v4-*.txt`.

## How to reproduce

```bash
# 1. Fresh DB schema + bootstrap a workspace
bun run docker:up
bun run db:push:ci
bun run db:bootstrap -- --email bench@mnemis.test --workspace mnemis-benchmark

# 2. Start worker + api allowing local sources (leave ANTHROPIC_API_KEY
#    unset to get the contextual-prefix-disabled numbers above)
export MNEMIS_ALLOW_LOCAL_SOURCES=true
export MNEMIS_LOCAL_SOURCE_ROOTS=$(pwd)
bun run worker:dev &
bun run api:dev &

# 3. Index once
export MNEMIS_API_URL=http://localhost:8787 MNEMIS_API_KEY=mn_…
bun run benchmark > reports/raw/baseline-hybrid.txt
SOURCE_ID=<id printed above>

# 4. Swap reranker provider per run (kill+restart the API, keep worker)
MNEMIS_RERANK_PROVIDER=voyage bun run api:dev &
MNEMIS_BENCHMARK_SOURCE_ID=$SOURCE_ID bun run benchmark > reports/raw/baseline-voyage.txt

MNEMIS_RERANK_PROVIDER=local bun run api:dev &
MNEMIS_BENCHMARK_SOURCE_ID=$SOURCE_ID bun run benchmark > reports/raw/baseline-local.txt
```

## Caveats

- 10 queries is enough to expose a trend (no rerank ≪ local rerank < Voyage
  rerank) but too few for a published quality claim. Extend
  `packages/eval/data/mnemis-self/queries.json` before quoting these
  numbers externally.
- The corpus is the Mnemis repo itself, so vocabulary is unusually
  specific. BEIR or MTEB subsets would give a less biased view.
- The contextual prefix observation is corpus-specific. Re-evaluate with
  a docs-heavy dataset before disabling the feature globally.
- `Xenova/bge-reranker-v2-m3` is currently gated on Hugging Face
  (`Unauthorized access to file`). Default switched to
  `Xenova/bge-reranker-base`; override with `MNEMIS_LOCAL_RERANK_MODEL`
  when the v2-m3 repository opens up again.
- Voyage's embeddings API caps each batch at 120 K tokens. We lowered
  `MAX_BATCH` from 128 to 64 in `packages/embeddings/src/index.ts` to
  stay under the cap with contextual prefixes attached.
- Free Voyage accounts cap at 3 RPM / 10 K TPM, which blocks the
  indexing job entirely. A paid Voyage account is required to reproduce
  the rerank rows.
